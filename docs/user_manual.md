# 사용자 매뉴얼

Nexus 대시보드의 설치부터 실행, 각 기능 사용법까지 안내합니다.

---

## 1. 설치

### 사전 요구사항

- **OS**: Windows (콘솔 API 및 Mutex 사용)
- **Python**: 3.12 이상
- **터미널**: Windows Terminal 권장 (유니코드/이모지 렌더링)

### 가상환경 및 의존성

```bash
# 프로젝트 루트에서 가상환경 생성
python -m venv .venv

# 의존성 설치
.venv\Scripts\pip.exe install -r requirements.txt
```

---

## 2. 환경설정 (env.toml)

프로젝트 루트에 `env.toml` 파일을 생성합니다. 앱 최초 실행 시 파일이 없으면 빈 파일이 자동 생성되며, 필수 항목이 누락되면 `ConfigError`와 함께 종료됩니다.

### 필수 항목

```toml
[DISCORD]
TEST   = "https://discord.com/api/webhooks/..."   # 테스트 로그 전송용 웹훅
LOG    = "https://discord.com/api/webhooks/..."   # 운영 로그 전송용 웹훅
STATUS = "https://discord.com/api/webhooks/..."   # 에이전트 상태 모니터용 웹훅
```

### 지갑 설정 (선택)

에이전트에서 `Config.WALLET("지갑이름")`으로 접근할 수 있는 지갑 정보를 등록합니다.

```toml
[WALLET.my_wallet]
SECRET_KEY = "..."
ADDRESS = "..."
# 필요한 키-값을 자유롭게 추가 가능
```

> ⚠️ `env.toml`은 `.gitignore`에 포함되어 있습니다. 절대 커밋하지 마세요.

## 3. 실행

### 일반 실행

```
start.bat
```

### 개발 모드 (Textual DevTools)

```
dev.bat
```

개발 모드에서는 별도 터미널에서 `textual console`로 DevTools를 연결하여 위젯 트리, 이벤트 로그 등을 실시간 확인할 수 있습니다.

> ⚠️ 반드시 bat 파일로 실행해야 합니다. `python src/main.py`를 직접 호출하면 `--from-bat` 인자가 없어 즉시 종료됩니다.

### 단일 인스턴스

Nexus는 Windows Mutex를 이용하여 동시에 하나의 인스턴스만 실행됩니다. 이미 실행 중인 상태에서 다시 실행하면 기존 창이 포커스됩니다.

## 5. Home 탭

시스템 로그를 확인하고 대시보드의 상태를 모니터링하는 탭입니다.

### 시스템 로그 뷰어

앱 내부에서 발생하는 이벤트(에이전트 시작/중지, 디스코드 에러 등)가 시간순으로 표시됩니다. 최대 500줄까지 유지됩니다.

### 성능 모니터

| 항목 | 설명 |
|---|---|
| LOG | 현재 로그 라인 수 / 500 |
| CPU | 대시보드 프로세스 CPU 사용률 |
| RAM | 대시보드 프로세스 메모리 사용량 (MB) |

### 버튼

| 버튼 | 기능 |
|---|---|
| **Reset** | 시스템 로그 전체 삭제 및 카운터 초기화 |
| **Export** | 현재 시스템 로그를 `LOGS/` 폴더에 텍스트 파일로 저장 |

## 6. Agent 탭

에이전트를 관리하는 핵심 탭입니다.

### 에이전트 리스트 (좌측)

`NEXUS_AGENT/` 폴더의 `.py` 파일들이 자동으로 표시됩니다.

#### 상태 아이콘

| 아이콘 | 상태 | 의미 |
|---|---|---|
| ○ | SLEEPING | 대기 중 (미실행) |
| ○●(깜빡임) | RUNNING | 실행 중 |
| ⦿ | STOPPING | 종료 대기 중 |
| ◎ | STOPPED | 종료됨 |

#### 추가 표시

| 표시 | 의미 |
|---|---|
| 🗎✗ | 파일이 디스크에서 삭제된 에이전트 |
| 🅃 | 디스코드 테스트 모드로 실행된 에이전트 |

### 로그 뷰어 (우측)

선택한 에이전트의 실시간 로그가 표시됩니다. 최대 500줄까지 유지되며, 로그 레벨에 따라 색상이 다르게 표시됩니다.

### 제어 버튼

| 버튼 | 기능 | 설명 |
|---|---|---|
| **▶ Start** | 에이전트 실행 | 운영 모드로 실행. 로그가 디스코드 LOG 채널로 전송됨 |
| **▷ Start** | 테스트 실행 | 테스트 모드로 실행. 로그가 디스코드 TEST 채널로 전송됨 |
| **■ Stop** | 에이전트 중지 | `CTRL_BREAK_EVENT` 시그널 전송. 5초 초과 시 강제 종료 |
| **∅ Cache Clear** | 초기화 | STOPPED 상태의 에이전트를 SLEEPING으로 되돌리고 로그 삭제 |
| **⎙ Save Log** | 로그 저장 | 에이전트 로그를 `LOGS/` 폴더에 텍스트 파일로 저장 |

### Disk Refresh 버튼

에이전트 리스트 하단의 `↻ Disk Refresh` 버튼을 누르면 `NEXUS_AGENT/` 폴더를 다시 스캔하여 새로 추가/삭제된 파일을 반영합니다.

## 7. 디스코드 알림

앱 실행 3초 후 디스코드 웹훅 연동이 자동으로 시작됩니다.

### STATUS 채널

에이전트 상태가 하나의 메시지에 실시간으로 갱신됩니다 (PATCH 방식). 앱 종료 시 해당 메시지는 자동 삭제됩니다.

### LOG / TEST 채널

에이전트 로그가 3.5초 간격으로 일괄 전송됩니다.

- **운영 모드** (`▶ Start`)로 실행한 에이전트의 로그 → `LOG` 채널
- **테스트 모드** (`▷ Start`)로 실행한 에이전트의 로그 → `TEST` 채널

---

## 8. 종료

### 정상 종료

콘솔 창의 **X 버튼**을 클릭하면:
1. `CTRL_BREAK_EVENT`가 발생하여 모든 에이전트 프로세스를 정리합니다.
2. 디스코드 상태 메시지를 삭제합니다.
3. 최대 4.5초간 정리 시간을 확보한 뒤 종료합니다.

### 강제 종료

`atexit` 핸들러가 등록되어 있어, 예기치 않은 종료 시에도 에이전트 프로세스를 `kill`합니다.

## 9. 트러블슈팅

| 증상 | 원인 | 해결 |
|---|---|---|
| `start.bat을 이용하여 실행해주세요` | `python src/main.py` 직접 실행 | `start.bat` 사용 |
| `env.toml 파일이 비어있습니다` | `env.toml` 미작성 | 위 2번 환경설정 참고 |
| `DISCORD 설정이 누락되었습니다` | `env.toml`에 `[DISCORD]` 섹션 누락 | TEST, LOG, STATUS 키 모두 작성 |
| `Nexus가 이미 실행 중입니다` | 중복 실행 시도 | 기존 창 확인 또는 작업관리자에서 종료 |
| 에이전트 리스트가 비어있음 | `NEXUS_AGENT/` 폴더에 `.py` 파일 없음 | 에이전트 파일 생성 후 `Disk Refresh` |
| 에이전트 실행 시 `main() 함수를 찾을 수 없습니다` | 에이전트 파일에 `main()` 미정의 | `def main():` 함수 작성 필요 |
| 디스코드 메시지가 전송되지 않음 | 웹훅 URL 오류 또는 네트워크 문제 | `env.toml`의 URL 확인, 시스템 로그 확인 |
